Cloud Run Provisioning Options

To deploy an application to Google Cloud Run, we first need to provision the infrastructure. This means telling Google Cloud to create the resources (Cloud Run service, Artifact Registry for Docker images, and Service Accounts for security). We have three main ways to do this.

ClickOps (Cloud Console)

Manually clicking through the Google Cloud web interface to create resources.

Pros: Great for learning and one-off experiments.

Cons: Not repeatable. Error-prone. Cannot be version-controlled or reviewed.

Terraform

The industry standard for Infrastructure as Code (IaC). Uses a declarative language called HCL (HashiCorp Configuration Language).

Pros: Huge ecosystem, widely understood.

Cons: Requires learning a new domain-specific language (HCL). Context switching between TypeScript and HCL.

Pulumi

An IaC tool that lets you write infrastructure using general-purpose programming languages like TypeScript, Python, or Go.

Pros: Use the same language (TypeScript) for both your app and your infrastructure. Share types and logic.

Cons: Smaller ecosystem than Terraform.
