# INC-IO Engine

The core rules engine and document management system that validates payloads, resolves identities, and orchestrates activities.

## Language

**DocumentType**:
The structural definition for a class of managed documents.
_Avoid_: Business entity, generic schema, recordType

**DocumentSchema**:
The subset of a `DocumentType` defining the shape of the data payload.
_Avoid_: recordSchema

**DocumentUiSchema**:
A highly condensed, abstract blueprint that maps `DocumentSchema` fields to UI concepts (widgets, labels, reactive behaviors). Separated from the core domain.
_Avoid_: documentUiConfig, FormSchema

**SpaceUiSchema**:
The abstract blueprint mapping `DocumentSpaceType` attributes to UI concepts.
_Avoid_: spaceUiConfig

**Document**:
A validated, immutable instance perfectly satisfying a `DocumentType`.
_Avoid_: Payload, record

**Activity**:
A declarative instruction generated by the core domain to be executed by a driven adapter. Must only contain serializable domain data (`payload`).
_Avoid_: Side-effect, action

**ExecutionContext**:
An ephemeral side-channel object passed alongside an Activity, containing secure credentials (e.g., OAuth tokens) and environment-specific resources. Strictly separated from the `payload` to prevent secrets from being logged or stored.
_Avoid_: WorkspaceContext (when in the domain)

**ActivityOutput**:
A generic patch or effect produced by an executed Activity, containing fields like `documentDataPatch` or `contextVariables` that the engine merges into the workflow context.
_Avoid_: Execution result, side-channel mutation

**DocumentField**:
A definition of a pure data property expected within a `Document`.
_Avoid_: Property, variable, recordField

**CalculatedField**:
A read-only field derived dynamically from the base payload. Cannot reference other calculated fields or identity properties.
_Avoid_: Derived field, formula field

**Identity**:
Templates generating unique identifiers (e.g., `id`, `idDocument`, `idGroup`) based on the payload, used in workflows and activities.

**LookupField**:
A `DocumentField` that links to and validates against predefined option tuples, enriched to provide both machine-friendly identifiers and human-friendly display names.
_Avoid_: ListField

**StorageContext**:
A configuration block defining storage identifiers and paths evaluated against the enriched `Document` payload.
_Avoid_: StorageConfig, StorageMapping, DriveContext

**Manifest**:
The root registry of available `DocumentType` schemas and `AppConfiguration`.

**AppConfiguration**:
Domain and administrative defaults that govern application behavior, distinct from environment-bound secrets.

**Workspace Addon**:
The primary user interface, acting as a driving adapter to the core engine.

**UiProcessManager**:
The command/write model orchestrator in the CQRS UI pattern. Responsible for evaluating UI state and events, decomposing information to pass to domain features via ports, and translating display names into technical keys. Does not build UI structures.
_Avoid_: UiController, StateManager

**SchemaDrivenUi**:
The read-only model orchestrator in the CQRS UI pattern. A generic engine that receives clean view state from the `UiProcessManager` and constructs abstract `UiView`s. Responsible for fetching or resolving display names for rendering.

**UiBlock**:
A pure presenter function inside `SchemaDrivenUi`. Maps data and UI schemas into modular, abstract UI elements.
_Avoid_: Component, Widget (when referring to the composite), Module, Renderer

**UiView**:
A compiled, declarative view model emitted by `SchemaDrivenUi`. Flattens `UiBlock` outputs into a generic payload consumed by dumb infrastructure renderers.
_Avoid_: GoogleCard, UiCard, JsonResponse

**UiViewSchema**:
A declarative layout orchestrating which `UiBlock`s compose a `UiView`. Hard-coded within infrastructure-specific driving adapters inside `SchemaDrivenUi`.
